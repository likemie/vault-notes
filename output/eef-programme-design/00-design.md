# EEF 项目条目与卡片设计

设计日期：2026-10-27。依据本地快照 `raw/EEF/EEF_promising_programmes_full .json`，导出时间为 2026-10-27T05:54:54.710Z。本次只设计模板，未核对网页现状，未阅读评估 PDF。

## 数据范围

快照包含 23 个项目、38 个评估或推广页面，以及 74 条分组结果。38 个页面中，35 个标为 `evaluation`，3 个标为 `scale_up`；6 个页面没有结构化结果。附件记录共 158 条，包含评估报告、方案、统计分析计划和附录，也包含同一报告的不同版本。

`status: complete` 表示抓取完成。项目是否结束、评估是否完成，以及是否已有结果，需要分别核对页面信息。

## 条目、评估与卡片

| 对象 | 保存位置与类型 | 承载内容 |
| --- | --- | --- |
| 具名项目 | `wiki/facts/<region>/<Programme Name>.md`；`type: fact`、`subtype: program` | 项目目标、实施方案、发展历程、评估概况及适用条件 |
| 一次评估 | 先保留在项目数据中；读完独立报告后建立对应 Argument 与 source record | 研究设计、比较组、分析样本、结果、推论和局限 |
| 项目卡片 | 项目页内展示，也可挂到确有联系的 Concept 条目 | 项目简介、EEF 页面指标、评估入口及分组结果 |
| 工具包策略 | 复用已有 Concept 及 EEF 工具包模块 | 通用教学策略的综合证据 |

同一项目的多个试验放在一个项目页中。不同测量结果放入同次评估的结果表。报告的版本更新先核对差异，保持同一研究身份；独立的试验才建立独立评估记录。

项目页采用现有 Program 骨架，保留“背景、方案设计、推进历程、成效评估、相关条目”五部分。实施条件与成本分别展开；争议有可靠材料时再写。

## 建条前的身份核对

23 个项目对应 23 个待审候选，建条数量由现有条目匹配与版本核对决定。

- `Success for All` 已有 `wiki/facts/us/Success for All.md`。先核对英国实施与已有项目的关系，再决定在原条目中增加英国评估，或建立有独立实施方案的地域版本；暂不移动原条目。
- `Dialogic Teaching` 已是 `Dialogue in Education` 的 alias。具名项目建议以 `Dialogic Teaching Programme` 为候选标题；中文 alias 明确为项目名，避免与通用教学概念共用自动补链词。
- `NELI Preschool` 与 `Nuffield Early Language Intervention` 分别审查对象和实施版本。后者列出的相关链接包含前者的评估，链接出现本身不能决定归属。
- Mathematics Mastery 的小学项目页和中学项目页互列评估链接；当前 `programme_url` 也不足以单独区分归属。匹配时同时核对项目版本、标题和教育阶段。

新标题优先保留英文项目专名，避免加入抓取年份。项目稳定键采用 EEF 项目 URL 的末段；评估稳定键采用评估 URL 的末段。URL 参数变化不产生新研究。

## 项目页结构

1. **项目定位与背景**：说明项目面向谁、解决什么问题，区分开发方、交付方、资助方和独立评估方。立项时间缺失时写待核；试验完成年月保留在评估记录中。
2. **方案设计**：用现有四格 `[!policy-design]` 呈现目标、对象、干预措施和实施控制。项目的实施要求与研究的随机分配设计分开说明。
3. **实施安排与成本**：说明课时、频率、小组人数、实施人员、培训及准备时间。成本保留币种、单位、估算年份或试验版本、摊销期限与假设。
4. **推进历程**：逐项记录确有证据的研发、试点、评估和推广节点。仅有一次评估也单列章节，不补造完整发展史。
5. **成效评估**：展示项目卡片、评估列表和分组结果，并解释实际检测的指标及适用范围。
6. **实施条件与证据局限**：区分实施者反馈与因果结果，保留样本构成、测量局限和数据冲突。
7. **相关条目**：用现有 `[!entry-map]` 说明与概念、机构和报告的具体联系。

项目页 YAML 沿用标准 Program 字段。`period` 写项目周期；`initiator_organization` 经核验后填写发起主体。EEF 资助评估的事实放在正文，不能据此推定 EEF 是项目开发方。`related_*` 留空并由正常关系同步生成。页面不增加 `sources` 或 `## 来源`。

稳定项目键、抓取时间、原始网页定位和试验关联存入数据层。首次只依据网页建立的条目使用 `status: draft`。正式报告读完后，正文按 APA 规范链接对应 Argument；模板中的网页快照出处仍保留其核验层级。正式入库前需明确这类网页数据记录与现有“新条目须由 Argument 提及”检查的衔接，本设计不添加豁免。

## 卡片三层结构

| 层次 | 展开状态 | 内容与行单位 |
| --- | --- | --- |
| 项目总览 | 展开 | 项目名称、简述、EEF 项目页额外进步月数或定性描述、证据阶段、项目页挂锁评级、成本及口径 |
| 评估记录 | 默认折叠 | 每个独立评估或推广页面一行，列出试验类型、页面状态、学校与学生数量，以及报告入口 |
| 分组结果 | 默认折叠 | 每个“评估 × 指标 × 人群 × 测量时点或干预版本”一行，保留月数、原始效应量、评级及显著性说明 |

项目总览不合计跨试验的学校和学生数量，也不自行平均额外进步月数。相关页面数按核实后的独立页面去重；同时区分有结果评估、暂无结构化结果页面与推广页面。

结果行用指标名称区分全样本、享有免费校餐资格的学生（Free School Meals，FSM）以及享有早期教育补助资格的儿童（Early Years Pupil Premium，EYPP）。正式译名在建条时复核。结果不默认全部属于主要结局；没有主要结局标识时只写“页面列示结果”。

## 字段映射与显示规则

| 展示字段 | 原始字段或位置 | 处理规则 |
| --- | --- | --- |
| 项目简介与实施方案 | `programmes[].description`、`sections` | 简介用于筛选；细节回到对应 section，保留可定位的出处 |
| 项目页影响 | `impact_months_rating`、`impact_type`、`impact_label`、`impact_symbol` | 数值存在时显示带符号月数；只有定性描述时显示译文，并标明月数未提供 |
| 证据阶段 | `evidence_type` 或 `metrics.type_of_trial` | 保留效能试验、成效试验等原始分类；清除混入字段的词条释义时保留原值供追溯 |
| 证据强度 | `evidence_strength_rating/total/status` | 项目页与评估页分别保存；优先显示数值与分母，如 `4/5` |
| 结果评级 | `trial_outcomes[].security_strength/total/status` | 仅作用于所在结果行；“不适用”和“未评级”分别展示，不沿用项目页挂锁数 |
| 结果月数与效应量 | `trial_outcomes[].impact_months/effect_size` | 缺失保持缺失；数值 0 保持 0；页面未标明效应量类型时列名用“原始效应量”，不补写 d 或 g |
| 显著性 | 结果对应的 `sections`、`results_text` 或报告 | 当前没有结构化显著性字段；逐结果核对语境，未报告写“未报告” |
| 试验样本 | `metrics.pupils`、`metrics.schools` | 原样保留页面口径；未确认随机分配样本、分析样本或实施覆盖数时，不替换成另一种口径 |
| 完成时间 | `metrics.completed` | 标为页面所列完成时间；保留原文。报告上传时间与试验完成时间分别保存 |
| 实施成本 | 项目页成本 section、成本等级字段 | 金额保留单位与估算条件；成本等级与金额分开。试验拨款 `metrics.grant` 单列 |
| 文件入口 | `documents`、`report_link_details` | 区分报告、方案、统计分析计划与附录；保留版本，不能简单取第一个 PDF |
| 项目与评估的关系 | `trial_urls`、`programme_url`、相关 section | 合并产生候选后人工核对；普通相关链接不能自动变为本项目试验 |

## 已发现的模板边界案例

- Emotion Coaching 的项目页只有“小幅正向影响”描述，没有额外进步月数。其某项自我调节结果列出原始效应量 `0.07`，卡片保留该值，月数显示“未提供”。
- 1stClass@Number 1 首次试验列出 `+2` 个月，结果文字同时明确主要结果未达统计显著。月数、挂锁评级与显著性分别显示。
- 1stClass@Number 1 项目简介称最近试验涉及 226 所学校，第二次评估页的 `metrics.schools` 为 235。设计样例保留两个出处，标记样本口径待核。
- 同一快照将第二次试验的完成时间写为 2026 年 10 月，而评估报告附件上传日期为 2025 年 6 月 25 日。卡片保留页面字段，并提示核验时间含义；不据附件日期自行改写完成时间。
- 结果评级字段同时出现 `ok`、`not_applicable` 和 `not_rated`，三者分别处理。

## 现有模板与样式的衔接

现有 `wiki/templates/template-eef-programme.md` 是脚本生成样板；现有样式把项目表固定为六列、试验表固定为七列，并通过列位置生成表头。直接改列内容会造成表头含义错位。

本目录给出下一版结构草案：项目表改为四列；评估列表与分组结果分开。建议继续使用 `[!eef-programme]`、`[!eef-trials]`，为分组结果增加 `[!eef-outcomes]`。后者尚未登记样式。本次的 Markdown 可用于检查内容结构，尚未完成 Obsidian／Quartz 的视觉验收。

采纳后再同步修改模板生成器、`CALLOUTS.md` 和相关 CSS，并核对 `[!eef*]` 模块的补链与关系跳过行为。本次未更改这些文件。
