### 易混淆辨析

| 容易混淆的对 | 判断规则 |
|---|---|
| `[!debates]` vs `[!tension]` | debates = **≥2 方**，按争议类型分卡，每卡可写说明；tension = **恰好 2 方**，蓝/红对立，有 VS 徽章 |
| `[!debates]` vs `[!critique]` | debates = 各方**都有论据**，无对错；critique = **外部视角**单方向指出缺陷 |
| `[!tension]` vs `[!critique]` vs `[!warning]` | tension = 两方争论；critique = **外部**指出缺陷；warning = **作者自述**局限 |
| `[!warning]` vs `[!critique]` | warning = **原文作者**自述局限；critique = **读者/外部**批评视角 |
| `[!tension]` vs `[!contrast-table]` | tension = 两方**对立立场**（蓝/红，有 VS 感）；contrast-table = 两个事物**属性对比**（无对错之分） |
| `[!claim]` vs `[!conclusion]` | claim = 论证**起点**的可争辩主张；conclusion = 论证**结束**后的总结 |
| `[!finding-cards]` vs `[!evidence-grid]` | finding = 本研究的**积极结论**；evidence = 支持某主张的**证据清单** |
| `[!timeline]` vs `[!phase]` | timeline = 逐条年份列表；phase = 有起止年代的**叙事段落** |
| `[!contrast-table]` vs `[!tension-table]` | contrast = 两个事物整体对比；tension-table = 同一维度上两个**对立立场** |
| `[!dimension]` vs `[!concept-lens]` | dimension = 分析**视角/层面**（≥3）；concept-lens = 固定三联（含义/用途/边界） |
| `[!chain-link]` vs `[!proposition-chain]` | chain-link = 叙述式推理**链节**；proposition-chain = 形式化**命题**列表 |
| `[!implication]-` vs `[!conclusion]` | implication = 从发现**延伸出去**的后果；conclusion = 本论证的**收束** |

## 使用原则

- callout 服务阅读层次。普通说明段不要强行包进 callout。
- 同一节内 callout 不宜过密；内容少于 3 点时优先用散文或普通列表。
- 任何 callout 可加 `+`/`-` 控制折叠，例如 `[!stat-cards]-`。
- 嵌套不超过 2 层。列表项内嵌套用 `>    > [!type]`（外层 `>` + 3 空格）。
- Mermaid 节点标签保持单行；流程图默认 `flowchart LR`。

## 论证结构与推理图

| Callout | 用途 |
|---|---|
| `[!logic-map]` | Mermaid 论证图、机制图、因果链 |
| `[!mechanism-map]` | 理论机制图；图后需配 `[!proposition-chain]` 或散文解释 |
| `[!proposition-chain]` | 核心命题链，按前提 → 机制 → 条件 → 结果组织 |
| `[!argument-steps]` | 分步论证结构，适合全书或长篇论证 |
| `[!chain-link]` | 论证链：单个 callout 内用列表列举各链节；金色垂直脊线 + 自动编号节点圆；标题徽章显示 `CHAIN` |

**`[!chain-link]` 写法**：整条论证链写在**一个** callout 里，每个链节是一个 `- **标题** 内容` 列表项。

```markdown
> [!chain-link] 论证链名称（可选）
> - **链节一：研究起点的误区**
>   许多新手从过于宏大的课题出发……
> - **链节二：研究不是观点佐证**
>   新手研究者倾向于……
> - **链节三：窄化通向严谨**
>   研究课题只是地图上的一个点……
```

- 序号圆圈（1、2、3…）由 CSS 自动计数，金色脊线自动连接各节点
- 每个 `-` 列表项首个 `**粗体**` 作为链节标题，渲染为金色下划线行
- 链节数量不限，卡片式布局，悬停高亮
| `[!assumptions]` | 层层递进的理论假设或前提 |
| `[!axioms]` | 公理化前提或不可再拆的基础命题 |

## 学术争论与对立

> **四类内容严格区分，不要混用**
> - **争论**（debate）：两方或多方都有论据，各有立场，没有明确对错 → `[!debates]` 或 `[!tension]`
> - **批评**（critique）：从**外部视角**指出某理论/方法的具体缺陷 → `[!critique]` 系列
> - **局限**（limitation）：**作者自述**或普遍公认的边界/风险 → `[!warning]`

| Callout | 用途 |
|---|---|
| `[!debates]` | 多方学者对同一问题各持立场的学术争论；**按争议类型**分卡，每卡含说明文字 + 学者索引；适合 2 个以上立场、无明确对错 |
| `[!tension]` | 恰好两方正面对立；蓝（奇数项）vs 红（偶数项）双栏布局，中央 VS 圆形徽章；**只用于二元范式冲突** |

### `[!debates]` 写法

**两层嵌套结构**：外层是 `[!debates]`（一个 `>`），内层每张卡是一个**内嵌 callout**（两个 `> >`）。

```
外层 [!debates]
  └── 内嵌卡 1：争议类型一（> >）
        ├── 说明段落
        └── 学者索引列表
  └── 内嵌卡 2：争议类型二（> >）
        ├── 说明段落
        └── 学者索引列表
```

**书写规则：**

1. 外层写 `> [!debates] 标题`，下方空一行后开始写内嵌卡
2. 每张内嵌卡写 `> > [!abstract] 争议类型名`（`[!abstract]` 可换任意 callout 类型，CSS 统一覆盖外观）
3. 内嵌卡标题行后紧接说明段落，**不要省略说明文字**——这是 `[!debates]` 区别于普通列表的关键
4. 说明段落后空一行，写学者索引列表：`- **学者名（Year）** 一句话立场。[[Argument|(Author, Year)]]`
5. 加 `-` = 默认折叠（`[!abstract]-`）；不加 = 默认展开
6. 卡片颜色按添加顺序自动循环：蓝 → 红 → 绿 → 琥珀 → 紫

```markdown
> [!debates] 学术争议
>
> > [!abstract] 目标争议
> > 说明各方在政策目标上争什么，背景与核心问题所在，可以多句话。
> >
> > - **Smith（2010）** 认为目标过于宏观，缺乏可测量指标。[[Argument_Smith_2010|(Smith, 2010, p. 45)]]
> > - **Jones（2015）** 认为目标恰当，批评执行层面而非目标本身。[[Argument_Jones_2015|(Jones, 2015, p. 23)]]
>
> > [!abstract]- 工具争议
> > 说明政策工具的效果之争（加 - 默认折叠，点击展开）。
> >
> > - **Lee（2018）** 认为工具产生副作用，挤压地方自主空间。[[Argument_Lee_2018|(Lee, 2018, p. 67)]]
```

**注意**：外层相邻两张卡之间只留一个空白 `>` 行（单个 `>`，不是空行），否则 Obsidian 会断开嵌套结构。

### `[!tension]` 写法

**平列两项**，奇数项自动渲染为蓝方（左），偶数项为红方（右），中央自动出现 VS 圆形徽章。

**书写规则：**

1. 列表项**只能写两项**——多写第三项会破坏双栏布局
2. 奇数项（第一条）= 蓝方，偶数项（第二条）= 红方，顺序不能颠倒
3. 每项写法：`- **立场名** 论点内容。[[引用]]`——`**立场名**` 自动渲染为该方颜色
4. 不适合用于有三方以上、或者需要详细说明背景的争论（改用 `[!debates]`）

```markdown
> [!tension] 两方对立标题
> - **立场 A（蓝方）** 蓝方核心论点，说明其立场的前提和依据。[[Argument_Author_Year|(Author, Year, p. X)]]
> - **立场 B（红方）** 红方核心论点，与蓝方的直接分歧所在。[[Argument_Author_Year|(Author, Year, p. X)]]
```

视觉效果：蓝色卡（左）| VS | 红色卡（右），hover 时蓝方向左滑出，红方向右滑出。

### 选择规则

| 情形 | 用哪个 |
|---|---|
| 多个学者/学派各持一说，争议有背景可说明 | `[!debates]` |
| 恰好两方，范式/框架正面对立（非此即彼） | `[!tension]` |
| 你自己在指出某立场的缺陷 | `[!critique]` |
| 原文作者自述边界/限制 | `[!warning]` |

## 局限与风险

**作者自述**或普遍公认的边界，不含外部批评视角。

| Callout | 用途 |
|---|---|
| `[!warning]` | 局限、风险、重要例外；**只写原文明确自述的内容**；`[!caution]` `[!attention]` 为别名 |
| `[!danger]` | 严重错误或致命风险，比 warning 级别更高；`[!error]` 为别名 |
| `[!failure]` | 失败案例、缺失数据、不成立的假设；`[!fail]` `[!missing]` 为别名 |
| `[!bug]` | 方法漏洞、逻辑 bug、操作化错误 |
| `[!challenges]` | 论证困难或挑战，琥珀色编号列表；适合明确标出若干已知困难 |

## 外部批评

**读者或他人视角**对某理论/方法/论证的批评，区别于作者自述局限。

| Callout | 用途 |
|---|---|
| `[!critique]` | 通用学术批评；列表项渲染为 **2 列卡片网格**，序号徽章位于右上角 |
| `[!critique-method]` | 方法论或统计错误（钢蓝）；2 列卡片网格 |
| `[!critique-logic]` | 逻辑或概念矛盾（紫）；2 列卡片网格 |
| `[!critique-data]` | 实证或数据反例（琥珀）；2 列卡片网格 |
| `[!critique-fatal]` | 根本性缺陷（深红，左边框加宽）；单列布局，保留完整描述空间 |

## 表格布局

这组 callout 控制表格的**列宽和标题结构**，选哪个取决于数据排列方式，而非内容语义。

| Callout | 用途 |
|---|---|
| `[!col1-table]` | 首列固定宽（28%）标签列，其余列均分；适合术语对照、键值说明 |
| `[!seq-table]` | 首列由 CSS counter 自动注入序号圆圈，Markdown 首列留空；其余列数不限；适合有序步骤表 |

**`[!seq-table]` 写法**：直接写普通 Markdown 表格，CSS 自动在最左侧注入序号列，内容列数量不限。

```markdown
> [!seq-table] 研究设计步骤
> | 步骤 | 说明 | 工具 |
> |---|---|---|
> | 确定研究问题 | 收窄至可研究比例 | 文献回顾 |
> | 设计研究方案 | 选择方法论框架 | 研究日志 |
> | 收集数据 | 访谈 / 问卷 / 文本 | NVivo |
```

| `[!dual-header]` | 行列双标题矩阵；左上角交叉格最深，行头浅色；适合交叉对比表 |
| `[!tension-table]` | 理论张力对照表；首列为维度，后列为两种立场，行间有分隔线 |
| `[!contrast-table]` | 内容对比（见"比较与并列"）；无固定列宽，聚焦比较维度 |

## 评估

| Callout | 用途 |
|---|---|
| `[!strength]` | SWOT 优势（绿），徽章 **S**；列表项自动排为 2 列卡片网格 |
| `[!weakness]` | SWOT 劣势（红），徽章 **W**；列表项自动排为 2 列卡片网格 |
| `[!opportunity]` | SWOT 机会（蓝），徽章 **O**；列表项自动排为 2 列卡片网格 |
| `[!threat]` | SWOT 威胁（琥珀），徽章 **T**；列表项自动排为 2 列卡片网格 |
| `[!fit-grid]` | 三区适用评估：✓ 适合（绿）/ ⚠ 谨慎（琥珀）/ ✗ 不适合（红）；徽章"适用评估"；每区为独立 li |
| `[!indicators]` | 评价指标体系，三层：投入 / 过程 / 结果 |
| `[!lessons]-` | 案例分析后的经验、启示或教训；自动编号；**默认写 `-` 折叠** |
| `[!ethical-pyramid]` | 伦理层级金字塔表，行背景随层级递减 |
| `[!ethical-code]` | 伦理守则有序列表，条款间有分隔线 |

四个 SWOT callout 各自独立使用；每个 callout 内的列表项自动排为 2 列卡片网格，卡片 hover 时上浮。`[!fit-grid]` 是轻量单 callout 替代品，适合只需一次性"适用 / 谨慎 / 不适合"三分判断的场景。

## 引用

```markdown
> [!quote]
> 原文引用

> [!citation-card]- 引用主题
> 中文译文。[[Argument_Author_Year_Journal|(Author, Year, p. X)]]
>

```

外文材料英文原文使用斜体；中文材料附英文译文。每节最多 1–2 个 `[!citation-card]`，优先集中到页面后部。
